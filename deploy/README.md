# Deployment contract

The game should deploy as a static browser build unless future server-side features explicitly change this architecture.

## Release process

1. Start from a clean checkout of the exact release commit.
2. Record the full SHA.
3. Install from the lockfile.
4. Run `npm test`, `npm run build`, and `npm run check`.
5. Package the complete build; never copy only changed files into production.
6. Generate release metadata with source SHA, build time and check results.
7. Generate file hashes for the package.
8. Transfer/extract into a new versioned release directory.
9. Verify hashes after transfer.
10. Atomically switch the current release pointer.
11. Preserve the previous release for rollback.
12. Verify the public game, main JS/CSS, models, animation assets, audio and release metadata.
13. Record validation in `docs/reviews/release-validation.md`.

## Hosting isolation

If hosted beside Notsims on the OptiPlex, use a separate directory/listener/path and do not overwrite or reset existing Funnel/Nginx routes. A Not WWE release must be independently rollbackable.

## Release truth

A GitHub push is not a deployment. A deployment is not human acceptance. A green browser smoke is not proof of touch comfort, motion quality or audible output.

## Implemented commands

- `node deploy/release.mjs verify dist` checks exact clean source identity, complete manifest and every file hash. Development builds with uncommitted changes are rejected.
- `node deploy/verify-http.mjs https://HOST/notwwe/ FULL_SHA` checks identity, JS/CSS/SVG/HTML/JSON MIME and key asset hashes through the actual public path.
- `node deploy/release.mjs activate ROOT PACKAGE` verifies the complete package, requires exact-SHA human certification, copies into `ROOT/releases/SHA` and atomically changes `ROOT/current`. The previous pointer is retained.
- `node deploy/release.mjs rollback ROOT` verifies and restores the previous complete release atomically. The local test suite rehearses pointer swaps and corruption rejection in disposable directories.

Before activation, reviewers provide `certification.json` with `sourceSha`, `certified: true`, and `acceptance` entries for `desktop`, `ios`, `android`, `audio`, `originality`, and `gameplay`. Each entry requires `passed: true` and a named `reviewer`; retain actual observations/date/device alongside it. Add the certificate's SHA-256 to `SHA256SUMS.json` after review; do not edit packaged executable files. Metadata `certified: false` describes the build-stage candidate; the separate signed-off evidence file is the activation gate. No production certificate has been generated by this implementation.

Build/rehearse from a detached clean checkout using the committed lockfile. Point only the isolated NotWWE listener's static root at `ROOT/current` during an approved certified activation; retain the existing landing page as the first rollback release. Never reset Tailscale routes or other listeners. After switching, verify `/notwwe/`, `/notsims/`, and the existing root redirect; record old/new pointers and UTC time. Human production smoke remains separate.
